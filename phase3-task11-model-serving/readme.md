# Matching & Ranking v2 Model Serving Engine 

This module implements the **Matching & Ranking v2 Model Serving Engine** for the PlaceMux backend. It manages machine learning model deployments using **shadow mode**, **canary rollouts**, latency budget enforcement, and automated rollback mechanisms to ensure safe, observable, and reliable ranking model releases.

The platform enables engineering teams to validate new ranking models in production without impacting end users while providing controlled rollout strategies and immediate rollback capabilities.

# Core Architecture & Workflow

## 1. Model Deployment Modes

The ranking engine supports multiple deployment strategies.

Available deployment modes include:

- Shadow Deployment
- Canary Deployment
- Full Production Deployment
- Disabled

These deployment modes enable safe validation before exposing new models to all users.


## 2. Shadow Mode Inference

During shadow deployment:

- Production users continue receiving results from the baseline model.
- The new model executes in the background.
- Predictions are logged for comparison.
- No user-facing behaviour changes.

This enables safe model validation using live production traffic.


## 3. Canary Rollouts

The canary deployment strategy gradually exposes the new model to a configurable percentage of users.

Benefits include:

- Controlled traffic exposure
- Performance monitoring
- Risk reduction
- Incremental rollout


## 4. Automatic Rollback

If a deployment violates operational constraints such as latency budgets or stability targets, the platform allows immediate rollback.

Rollback features include:

- Disable deployment
- Restore baseline model
- Preserve inference history
- Maintain service availability

# Evaluator Validation Guide

Configure the required environment variables.

```bash
export BASE=http://localhost:3009/api/v1

export STUDENT_UUID="4b111d42-ab12-4211-8224-2da21e48bc02"
export TENANT_UUID="a1b23c44-dd55-66ee-77ff-88aa99bb0011"

export JOB_1="8a329d41-cc21-4112-9114-1da21e48bc01"
export JOB_2="8a329d41-cc21-4112-9114-1da21e48bc02"
```


## Step 1 — Configure Shadow Deployment

```bash
curl -X POST "$BASE/intelligence/deployments/configure" \
  -H "Content-Type: application/json" \
  -d "{
    \"model_version\": \"ltr_v2.1_xgboost\",
    \"deployment_mode\": \"shadow\",
    \"canary_traffic_pct\": 0,
    \"max_allowed_latency\": 150
  }"
```

### Expected Result

Returns **HTTP 200 OK**.

Example response:

```json
{
  "success": true,
  "deployment_mode": "shadow",
  "model_version": "ltr_v2.1_xgboost"
}
```

The model is successfully configured for shadow deployment without affecting production users.


## Step 2 — Execute a Ranking Request

```bash
curl -X POST "$BASE/intelligence/rank" \
  -H "Content-Type: application/json" \
  -d "{
    \"student_id\": \"$STUDENT_UUID\",
    \"tenant_id\": \"$TENANT_UUID\",
    \"candidate_job_ids\": [
      \"$JOB_1\",
      \"$JOB_2\"
    ],
    \"idempotency_key\": \"rank-req-token-001\"
  }"
```

### Expected Result

Returns **HTTP 200 OK**.

Example response:

```json
{
  "success": true,
  "served_by": "ltr_v1.0_baseline",
  "shadow_model": "ltr_v2.1_xgboost",
  "shadow_logged": true
}
```

The ranking returned to the user is generated by the baseline model, while predictions from the shadow model are stored in the inference logs for offline comparison.


## Step 3 — Promote Model to Canary Deployment

```bash
curl -X POST "$BASE/intelligence/deployments/configure" \
  -H "Content-Type: application/json" \
  -d "{
    \"model_version\": \"ltr_v2.1_xgboost\",
    \"deployment_mode\": \"canary\",
    \"canary_traffic_pct\": 50,
    \"max_allowed_latency\": 150
  }"
```

### Expected Result

Returns **HTTP 200 OK**.

Example response:

```json
{
  "success": true,
  "deployment_mode": "canary",
  "traffic_percentage": 50
}
```

The new model is now serving 50% of eligible production traffic while the remaining traffic continues using the baseline model.


## Step 4 — Roll Back Deployment

```bash
curl -X POST "$BASE/intelligence/deployments/rollback" \
  -H "Content-Type: application/json" \
  -d "{
    \"model_version\": \"ltr_v2.1_xgboost\"
  }"
```

### Expected Result

Returns **HTTP 200 OK**.

Example response:

```json
{
  "success": true,
  "deployment_mode": "disabled",
  "rollback_completed": true
}
```

The canary deployment is immediately disabled, and all traffic is safely redirected back to the baseline ranking model.
